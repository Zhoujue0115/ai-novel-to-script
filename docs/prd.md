# Product Requirements Document

# AI 小说转剧本工具 PRD

## 1. 产品概述

AI 小说转剧本工具是一款面向小说作者和内容创作者的 AI 辅助改编工具。用户可以输入 3 个章节以上的小说文本，系统将自动分析小说中的人物、场景、情节和对白潜力，并生成结构化的 YAML 格式剧本初稿。

该工具的目标不是一次性生成最终成片剧本，而是帮助作者快速获得一个可编辑、可调整、可继续打磨的剧本框架，降低小说改编为剧本的前期整理成本。

## 2. 背景与问题

很多小说作者希望将自己的作品改编为短剧、影视剧本或舞台剧本，但在实际改编过程中会遇到以下问题：

1. 小说文本通常以叙事为主，而剧本需要以场景、人物行动和对白为核心。
2. 长篇小说章节信息较多，人工整理人物、场景和剧情节点耗时较长。
3. 作者可能缺乏专业剧本格式经验，不知道如何将小说转换为标准化剧本结构。
4. 自由文本形式的 AI 输出不方便后续编辑、校验和二次加工。

因此，本项目希望通过 AI 将小说文本转换为结构化 YAML 剧本，让作者获得一个清晰、可编辑、可复用的剧本初稿。

## 3. 目标用户

### 3.1 小说作者

希望将自己的小说作品改编为剧本，但缺乏专业剧本创作经验的作者。

### 3.2 网文作者

希望快速评估小说章节是否适合改编为短剧、影视片段或分场剧本的网文作者。

### 3.3 编剧与内容创作者

希望快速整理原始小说素材，提取人物、场景、对白和剧情节点的创作者。

### 3.4 创作团队

需要统一剧本结构格式，方便多人协作修改和后续加工的团队。

## 4. 用户场景

### 场景一：小说作者快速生成剧本初稿

用户粘贴至少 3 个章节的小说文本，点击生成按钮，系统自动输出 YAML 格式的剧本初稿。作者可以在生成结果基础上继续修改对白、动作和场景描述。

### 场景二：作者整理小说中的人物和场景

用户希望从已有小说章节中快速提取主要角色、角色关系、故事发生地点和关键剧情节点，系统在生成剧本时同步输出角色列表和场景列表。

### 场景三：创作团队统一剧本格式

创作团队希望使用统一的 YAML Schema 来管理剧本内容。系统生成的剧本可以被继续编辑、导出和共享，便于后续协作。

## 5. 核心功能

### 5.1 小说章节输入

- 支持用户输入小说标题。
- 支持用户输入至少 3 个章节内容。
- 支持章节标题和章节正文。
- 当章节数量不足 3 个时，系统需要提示用户补充内容。

### 5.2 AI 剧本生成

- 根据小说内容自动生成结构化 YAML 剧本。
- 提取主要角色信息。
- 提取主要场景信息。
- 将小说叙事转换为场景、对白、动作和旁白。
- 保留来源章节引用，方便作者追溯原文。

### 5.3 YAML 展示

- 在页面中展示生成后的 YAML 文本。
- 支持用户复制 YAML 内容。
- 支持导出 `.yaml` 文件。

### 5.4 剧本预览

- 将 YAML 内容渲染为更易阅读的剧本预览。
- 按场景展示标题、地点、时间、出场人物、对白、动作和旁白。
- 方便用户快速检查生成结果是否符合预期。

### 5.5 YAML Schema 说明

- 提供一份 YAML Schema 设计文档。
- 说明每个字段的含义、类型和设计原因。
- 提供示例 YAML，方便用户理解输出格式。

### 5.6 结果校验

- 对生成结果进行基础 YAML 格式校验。
- 检查必要字段是否存在。
- 当 YAML 格式不合法时，提示用户重新生成或修复。

## 6. 页面结构

本项目采用单页工具型页面，主要分为三个区域。

### 6.1 输入区域

位于页面左侧或上方，用于输入小说内容。

包含：

- 小说标题输入框
- 章节输入区域
- 添加章节按钮
- 生成剧本按钮

### 6.2 YAML 输出区域

用于展示 AI 生成的 YAML 内容。

包含：

- YAML 文本展示框
- 复制按钮
- 下载 YAML 按钮
- YAML 校验状态提示

### 6.3 剧本预览区域

用于将结构化 YAML 渲染为剧本阅读视图。

包含：

- 角色列表
- 场景列表
- 场景详情
- 对白、动作、旁白分块展示

## 7. 输入输出定义

### 7.1 输入数据

用户输入的数据包括：

```json
{
  "title": "小说标题",
  "chapters": [
    {
      "index": 1,
      "title": "第一章",
      "content": "章节正文"
    },
    {
      "index": 2,
      "title": "第二章",
      "content": "章节正文"
    },
    {
      "index": 3,
      "title": "第三章",
      "content": "章节正文"
    }
  ],
  "style": "screenplay"
}
```

### 7.2 输出数据

系统输出的数据包括：

```json
{
  "success": true,
  "yaml_text": "title: ...",
  "validation": {
    "valid": true,
    "errors": []
  }
}
```
### 7.3 YAML 输出要求
生成的 YAML 需要包含：

- 剧本标题
- 来源章节
- 角色列表
- 场景列表
- 每个场景的时间、地点、人物
- 剧本内容块，包括对白、动作和旁白
- 改编说明
## 8. 非目标范围
为了保证比赛周期内项目可完成，本项目暂不实现以下功能：

不做用户登录注册。
不做多人实时协作。
不做数据库长期存储。
不做完整专业影视工业剧本排版。
不做分镜头自动生成。
不做超长篇小说全文一次性改编。
不做在线支付或商业化功能。

## 9. MVP 范围

第一阶段最小可用版本包含以下能力：

1. 用户输入小说标题和至少 3 个章节
2. 后端接收请求并进行输入校验
3. 系统调用大模型生成 YAML 格式剧本初稿
4. 后端对生成结果进行 YAML 格式校验
5. 返回 YAML 文本和校验结果给前端（前端 js-yaml 解析用于预览）
6. 前端展示 YAML 文本和剧本预览
7. 支持复制和导出 YAML 文件
